# Git Workflow Training

## ما تعلمته اليوم

اليوم تعلمت آلية العمل الاحترافية باستخدام Git، بنفس الطريقة المستخدمة داخل الشركات الحقيقية.

### الفروع (Branches)
- تعلمت إنشاء فروع منظمة حسب النوع: develop, feature/*, bugfix/*
- كل فرع يشتغل عليه شخص أو ميزة منفصلة، بدون التأثير على main مباشرة

### الدمج (Merge)
- دمجت عدة فروع (feature/login, feature/dashboard, bugfix/navbar) داخل develop
- تعلمت الفرق بين الدمج التلقائي (Fast-forward) ودمج يحتاج قرار

### حل التعارضات (Merge Conflict)
- واجهت تعارض حقيقي لما عدلت نفس السطر بفرعين مختلفين
- تعلمت كيف أفتح الملف يدويًا، أحذف علامات Git الخاصة، وأقرر المحتوى النهائي بنفسي

### أوامر المعلومات (Git History)
- git status: يعرض حالة المشروع الحالية
- git log: يعرض سجل كل التعديلات المحفوظة
- git diff: يعرض الفرق بين التعديلات غير المحفوظة والنسخة الأخيرة
- git branch / branch -a: يعرض الفروع المحلية والبعيدة
- git remote -v: يعرض رابط المستودع البعيد
- git show: يعرض تفاصيل آخر تعديل محفوظ

### Git Stash
- تعلمت كيف أخبئ تعديل غير جاهز مؤقتًا (git stash)
- واسترجعه لاحقًا بنفس المحتوى (git stash pop)

### Git Ignore
- تعلمت كيف أخلي Git يتجاهل ملفات معينة (زي node_modules أو .env) عن طريق ملف .gitignore

### Pull Request
- تعلمت كيف أنشئ طلب رسمي لدمج فرع بفرع ثاني عبر واجهة GitHub
- فهمت أهمية هذا الأسلوب بالشركات: يسمح بمراجعة الكود قبل الموافقة على الدمج

## خلاصة
اليوم كان تطبيق عملي شامل لكيف تشتغل فرق البرمجة الحقيقية مع Git، من إدارة الفروع للدمج وحل التعارضات والمشاركة عبر Pull Requests.
